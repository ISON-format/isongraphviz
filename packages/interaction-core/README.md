# interaction-core (IGR-IA/1: input layer)

`isongraph-visualize-interaction-core` is the renderer-neutral **input layer** of ISONGraph Visualize milestone V11. It turns abstract input events (pointer, wheel, touch, keys) into the frozen IGR/1 intents (`select`, `clear-selection`, `focus`, `focus-step`, `focus-first`, `focus-last`, `pan`, `zoom`, `fit`) plus a few host-level outputs, adds keyboard graph navigation and a keyboard alternative to the lasso, and has one DOM binder for a real page. Specification: `docs/isongraph-visualize-blueprint/32-INTERACTION-A11Y-EXPORT-DESIGN.md` (rev 3, sections 2 to 8); implementation notes and findings: `docs/isongraph-visualize-blueprint/reviews/32-implementation-notes-a1.md`.

Status: **implemented, not frozen.** The independent oracle corpus `fixtures/oracles-ia/` is a DRAFT (reference digest `f376c43b...a896`, pinned nowhere); every constant is PROVISIONAL and UNMEASURED; nothing here is claimed conformant (`claimable` stays false until the freeze). The package depends on `renderer-core` and `scene-core` (`./primitives` only, for `canonicalBytesSigned`): this is the declared departure CCR-V11-7 of design 2 and 18.3 (27 section 14 says renderer packages depend on `renderer-core` only; this is not a renderer, and the departure is the owner's to rule on). It implements the design as written and does not claim the ruling made. `layout-core` is a dev dependency of the tests.

## What is here

Core entry `.` (DOM-free: the core tsconfig has the ES2022 lib and no ambient types; no `node:*`):

- `step(machine, event, model, state, config?)`: the pure gesture machine `igr-input-machine/1` (click with the modifiers of the press, drag pan with the exact remainder rule, alt-drag lasso, two-pointer pinch, wheel accumulation in `bigint`, long press by `tick`, context menu, double click, keys through the binding table). It returns `{ machine, handled, outputs, wake_at? }`; nothing is mutated; the returned machine is frozen. `createMachine()`, `serializeMachine`, `parseMachine` (strict, at most 1 MiB, nesting scan, the invariants of 5.1) are for tests and diagnostics: a machine is never persisted across a reload. `serializeStep` writes a step result as IGR-CJ/1. `prepareConfig(config)` verifies a machine config once and returns a frozen copy that `step` accepts without verifying the binding table again (a raw config is verified at every `step`, O(table); the DOM binder prepares its config once).
- `validateEvent(event)`: the nine event shapes of 4.1 and their validation (first failure wins), an owned copy; `IaError` (`INVALID_EVENT`, `INVALID_CONFIG`, `INVALID_BINDINGS`, `INVALID_COMMAND`, `INVALID_MACHINE`, `INVALID_INPUT`, `RESOURCE_LIMIT`, and the codes the sibling packages add).
- `DEFAULT_BINDINGS` (33 rows), `verifyBindings(table)`, `serializeBindings`, `keyToken(domKey)`, `isKeyToken`: the binding table `igr-bind/1`; `Tab` is deliberately unbound (the widget is one Tab stop).
- `resolveNavigation(model, state, command, options?)`: `nav-spatial` (the pinned metric: closed 90-degree cone, then smallest `(p^2 + s^2, s, index)`), `nav-incident`, `nav-endpoint`, `nav-step`; `revealPan(model, state, target)`: the focus reveal rule (a frozen `pan` that brings the focused element into a 24 px margin box, or `undefined`).
- `lassoTargets(model, state, rect)`: the elements inside a milli-pixel rectangle (closed, exact centres in micro-pixels); the corner-node marquee (`m`, arrows, `Enter`) is the keyboard alternative.

Subpath `./dom`: `bindInteraction(container, target, options)`: the listeners (`pointerdown/move/up/cancel`, a non-passive `wheel`, `keydown`, `dblclick`, `contextmenu`, `focusin`), `touch-action: none` through the CSSOM, the conversion to integer milli-pixels, the clock clamp, key-repeat filtering, one `setTimeout` for `wake_at`, the focus entry rule and the flow of 5.8 (event, machine, intents, commit, `focusElement(state.focus)`, one `onCommit`). It requires `adapterPointer: "none"` and `adapterFocusRestore: "none"`: host assertions that the renderer adapter's own pointer handling and focus restoration are off (CCR-V11-6 adds those adapter options to the committed renderers; this package does not touch them). Smoke only: no row of the corpus claims any byte of it.

Nothing of `renderer-core` or `scene-core` is re-exported. Every function taking a caller-owned object reads each property once into plain data and refuses getters; element lookup uses `lookupElement` (a `Map`), never a plain object keyed by a graph string.

## Commands

Build order: `scene-core`, `layout-core` and `renderer-core` must have been built (their `dist/` is what the `file:` links resolve to), then `npm install` and `npm run build` here.

- `npm test`: the FAST suite (about 2 s): the 168 oracle rows of E, I, V, L, B tier-aware (`test/oracle.test.ts`, the runner `test/oracle/runner.ts` is shared with the mutation harness), the Appendix A figures (extracted from the design file with a visible skip when it is absent, plus a never-skipping check of the same figures against the tracked oracle files), unit tests for the argument discipline and the rules no row observes (`test/core.test.ts`), the binder against a fake DOM (`test/dom.test.ts`), the properties I1-I5 as the runtime rows D01-D03 with a handful of seeds (`test/properties.test.ts`), the `ext:` rows (`test/oracle/ext.ts`: checks the corpus does not observe, from the independent audit of stage A1), the surface and source audits, and a guard of the K table.
- `npm run test:slow`: one forked worker: many more property seeds and the **mutation matrix** (73 corpus mutants K and 25 extra mutants X for the audit findings, a few seconds).
- `npm run mutants`: the harness alone (`scripts/mutate.mjs`, `--only K01,K09`, `--jobs N`, `--timeout MS`); writes `.mutants/report.json` (git-ignored).
- `npm run check`: typecheck (tests, core without DOM, binder with DOM), `npm test`, `npm run test:slow`, `npm run build`, `npm run smoke`, `npm run demo:check`.
- `npm run smoke`: Node smoke (needs the builds): the default table, the transcripts of rows I50 and V30 and a lasso equal the tracked oracle bytes.
- `npm run smoke:browser`: Chromium smoke of the binder on the demo page through `playwright-core` (`./node_modules/.bin/playwright-core install chromium` once): real clicks, modifier presses, alt-drag lasso, wheel, drag, double click, Tab entry, arrows, reveal, marquee, Escape, ctrl+a, Tab out. One engine, one machine: a **smoke run, not browser qualification**.

## Tests and the oracle

`fixtures/oracles-ia` rows are run by `test/oracle/runner.ts`: `E` (59: event, config, command, machine bytes and rectangle validation; rows without a scene run on `G9` at 900x600), `I` (48 transcripts), `V` (40), `L` (8), `B` (13). `D01`-`D03` are runtime rows (tier `diff`): `D01` is property I1 on random transcripts through the real reducer in a closed loop with a headless renderer, `D02` is I2 (the pan telescoping sum), I3 (no mutation, round trip, the invariants of 5.1) and I4 (ranges), `D03` is spatial navigation against a test-local brute force of 7.2 and I5 (the reveal); seeds are the caller's and appear in the test names. The mutants whose named killers are rows of these families are in `scripts/mutants-table.mjs` as exact-text patches of a scratch copy of `src/` (production code has no switchable variants); `K84` (a plain object keyed by graph strings) is a TypeScript-only mutant realized as a label-keyed `??=` index.

## Demo (non-normative)

- `node scripts/replay.mjs <file.ison> | <scene.json> <layout.json> [--events file.json] [--size WxH] [--layout fixed|force] [--out file] [--page]`: source (or scene and layout) to a render model, an input transcript (the built-in click, drag, wheel and key sequence, or `--events`) replayed through the machine and a headless renderer, the outputs printed, the transcript written to `demo/out/`. `--page` also writes `demo/out/data.js`.
- `npm run demo:build` bundles `demo/page.mjs` into `demo/out/demo.js`; `demo/index.html` (serve the folder from `localhost`) paints a graph on a canvas through a tiny painter, driven by `bindInteraction` over a headless renderer. It has no accessible companion and is not claimed accessible.

## Limits and what is NOT claimed

- The binder is adapter code: its behaviour in other engines, with assistive technology, with touch on a real device, with IME or non-US layouts, and the scroll-trap behaviour of the non-passive wheel listener are not claimed. The default bindings are single-letter shortcuts (`e`, `s`, `t`, `m`, `a`) that can collide with screen-reader browse mode; a host rebinds them with `verifyBindings`.
- `set-hidden`, `resize` and `set-viewport` have no binding (host UI): 27 section 18's "every intent reachable by keyboard" is not met for them.
- Pointer-target resolution is the host's (`target.pick`); the machine never calls a hit test, and a stale target is treated as stated in 5.2.
- No performance claim: `step` does O(1) work for a pointer or wheel event of a pixel or line unit **with a prepared (or default) config**, O(N + E) for a key, click or marquee commit that reads the model, and O(state) for a page-unit wheel (it validates the state to read the viewport height); with a raw custom config it also verifies the binding table at every call (use `prepareConfig`); a wheel event can cause up to 8 zoom dispatches.
