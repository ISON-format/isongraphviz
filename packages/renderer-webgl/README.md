# renderer-webgl (IGR-GL/1)

`isongraph-visualize-renderer-webgl` is the WebGL2 renderer of ISONGraph Visualize milestone V7. It composes `createHeadlessRenderer` of `renderer-core` (every `Renderer` method is the inner one, unchanged, except `manifest`, the `fidelity` of `probe()` and the extra methods below) and draws the display list of the shared `display-list` library through a **GPU draw plan** `igr-gl/1`: three instance buffers (`edge`, `disc`, `arrow`), the element table and the label runs, with an exact integer guard rule that keeps every number below 2^24 (exact in `float32`). The labels are drawn by the companion 2D layer with the very replay of the Canvas renderer. Specification: `docs/isongraph-visualize-blueprint/31-CANVAS-WEBGL-DESIGN.md` (rev 4); implementation notes and findings: `docs/isongraph-visualize-blueprint/reviews/31-implementation-notes-step2.md`.

Status: **implemented, not frozen.** The independent oracle corpus `fixtures/oracles-gl/` is a DRAFT (reference digest `b87ff291...84c5e` (design rev 5), pinned nowhere) and `SHADER_SET_SHA256` is pinned in the design and in the tests, but the freeze (design 13.7) has not happened: every conformance report is `claimable: false`. The package depends on `renderer-core` **and `display-list`** (the declared departure CCR-2 of design 10.1, owner decision 1: no renderer imports another renderer); `scene-core` and `layout-core` are dev dependencies of the tests and the demo. Two further declared departures stand in the manifest and the adapter: the `dom` renderer declares `a11y.native-dom` and `a11y.companion-dom` `unsupported/NOT_IMPLEMENTED` (CCR-3, 8.4) and the adapter selects by `pick` (the drawn route) while `hitTest` stays the frozen chord (10.1). Owner decisions 1 and 16 are the owner's; this tree implements the design as written and does not claim them made.

## What is here

Core entry `.` (DOM-free; no `node:*`, no DOM lib):

- `planGl(list, limits?)`, `serializePlan(plan)`, `parseGlPlan(bytes)`: the pure planner with the guard rule (omit and list, or clip on integers with an exact Liang-Barsky), the writer and the strict reader (rules G1-G16; G12 includes the single-focus clause of design rev 5). `readGlPlan(bytes, { skip, lenient })` is the same reader with rules switchable: the tooling of the single-fault property of the `W` rows, of row `X07` and of the witness-honesty row `U11` (not a production variant of any output).
- `SHADER_SOURCES`, `shaderSetBytes()`, `SHADER_SET_SHA256`: the six GLSL ES 3.00 sources of Appendix B as constants; no text derived from a scene, a state, an option or the environment ever reaches a shader.
- `executePlan(gl, plan, resources, frame)`, `createGlResources(gl)`, `deleteGlResources(gl, r)`, `releaseGlContext(gl)`: the executor over the structural `Gl2Like` (a real `WebGL2RenderingContext` satisfies it); its logged call sequence is what a fake context records (rows `E`).
- `createGlController(canvas, options)`: the context-loss state machine of 7.6 (phases `created`, `ready`, `lost`, `failed`, `disposed`; events from the canvas listeners and `initialize`, `commit`, `render`, `dispose`). `probeWebgl(factory, need?, options?)`: capability detection over an injected factory of fresh canvases; it releases every context it creates and never reads an unmasked vendor or renderer.
- `createWebglRenderer(options?)`: the headless renderer; the backend is the plan. Extra methods: `displayList()`, `plan()`, `planBytes()` (bounded by `maxGlBytes`), `textCalls()` (the layer-8 stream the label layer receives), `pick(point)`, `elementBounds()`, `status()`. `glManifest(host, options?)`; `createWebglSubject(options?)` whose witness reads the **plan**, never `probe()`; `glWitness(plan)`; `readoutFromGl(plan)` (the readout of igr-xr/1 from the plan alone).

Subpath `./dom`: `createDomWebglRenderer(options?)`, the thin browser adapter: it probes on detached scratch canvases, requests the live `webgl2` context (the closed option `contextAttributes.failIfMajorPerformanceCaveat` reaches both the probe and `getContext`), stacks a 2D label canvas over the GL canvas, checks the drawing-buffer size, listens to `webglcontextlost`/`webglcontextrestored`, redraws the whole frame at every commit and maps one `pointerdown` through `pickDrawn`. A refused commit (a coordinate beyond 2^40 milli-pixels) **clears both canvases**, reports through `env.onError` and sets `status().failure`. No keyboard, wheel, move, focus or hover handler; **not claimed accessible** (design 8.3). It never calls `getError` or `readPixels`. It claims no conformance level.

`createDomWebglRenderer` also takes three additive adapter-only options (CCR-V11-6 of design 32, for hosts that bring their own input layer and accessible companion): `pointer: "builtin" | "none"` (default `"builtin"`; `"none"` registers no pointer listener; the context-loss listeners stay), `liveRegion: "builtin" | "none"` (default `"builtin"`; `"none"` creates and writes no status `div`) and `canvasLabel: "builtin" | "none"` (default `"builtin"`; `"none"` sets `aria-hidden="true"` on both canvases and writes no `role="img"` or `aria-label`, also after a context loss). The wrapper reads, validates (a bad value is `INVALID_INPUT/INVALID_VALUE`) and strips them; the shared composer and `createWebglRenderer` still reject them as unknown keys (`INVALID_INPUT/SCHEMA`). The type is `DomWebglRendererOptions`.

All constants are PROVISIONAL and UNMEASURED.

## Commands

Build order: `scene-core`, `layout-core`, `renderer-core` and **`display-list`** must have been built (their `dist/` is what the `file:` links resolve to), then `npm install` and `npm run build` here. The demo and the browser smoke also need `../renderer-canvas` and `../renderer-svg` built (the demo's try-chain imports all three DOM renderers).

- `npm test`: the FAST suite (about 2 s): every `gl:` row of the oracle by tier (the function rows `G B H W X E P`, the `both` rows against the renderer, the `subject` rows `B08`, `U01`-`U09`, `U13`, the controller rows `U20`-`U39` and the adapter row `U37`), unit tests for the planner, the guard rule, the reader (the single-fault property of every `W` row from the corpus's own `bad/FAULTS.tsv`), the executor, the controller, the probe, the options, the manifest, the renderer and the DOM adapter against a minimal fake DOM and a fake WebGL2 context, the differential rows `D01`-`D05` with a few seeds, the Appendix extraction test (skipped visibly when the git-ignored design file is absent) and its never-skipping tracked equivalent, the surface and source audits (exact dependencies, no DOM lib or `node:*` in the core, the security allowlist grep of 11.1, every `shaderSource` argument a constant, the K table guard).
- `npm run test:slow`: one forked worker: the IGR/1 kit run over `fixtures/oracles-igr` with `createWebglSubject` (rows `U10`-`U12`, level 2), many more differential seeds, a 20,000-node scale check and the reader-memory check (audit M-7) and the **mutation matrix** (the 156 corpus mutants plus 13 extra mutants killed by the `ext:` rows).
- The `ext:` rows (`test/oracle/ext.ts`, run by `test/extra.test.ts` and by the harness) pin what no corpus row sees: the audit's seven test gaps and the design rev 5 rules (single focus, the `(failed, R)` outcomes, the release rule); `scripts/mutants-extra.mjs` holds their 13 mutants.
- `npm run mutants`: the mutation harness alone (`scripts/mutate.mjs`, `--only K01,K09`, `--jobs N`, `--timeout MS`, `--no-heavy`); writes `.mutants/report.json` (git-ignored).
- `npm run check`: typecheck (tests, core without DOM, adapter with DOM), `npm test`, `npm run test:slow`, `npm run build`, `npm run smoke`, `npm run demo:check`.
- `npm run smoke`: Node smoke (needs both builds): the plans of three oracle examples equal the oracle bytes, the strict reader round-trips, the readout of the plan equals the list's, one creation and one frame run against a counting fake, the shader digest, the subject's witness. No GPU.
- `npm run smoke:browser`: Chromium smoke of the real adapter through `playwright-core` (`./node_modules/.bin/playwright-core install chromium` once): it reports whether the GL is a GPU or software, **compiles and links the six shaders** and reports every info log and GL error, draws the demo graph (non-blankness only, never identity: a decoded screenshot crop at the node centres), a real press selects a node and its identity resolves, a press on empty space clears, a press on a self-loop's apex selects the loop, a Tab emits no focus event, `WEBGL_lose_context` loses and restores the context (`status().contextLost`, an unchanged `probe()`, non-blank again), and a layout with coordinates of about +-10^9 px is drawn and the offset of its line from the ideal line is **recorded**. One engine, one machine, software GL allowed through the smoke seam: a **smoke run, not browser qualification**.

## Mutation testing

`scripts/mutants-table.mjs` lists the 156 mutants of the K table of design 13.5 (K01-K156) as exact-text patches applied to a **scratch copy** of `src/` (`.mutants/<id>/`); production code has no switchable variants. A mutant is KILLED when an oracle row fails, SURVIVED when none does, INCONCLUSIVE on a timeout (never counted as killed), and a patch that does not apply is a HARNESS-ERROR. `test/mutants-table.test.ts` checks that every patch still applies to the current sources. The mutations are this implementation's own realization of the corpus's one-line mutant texts; the named killing rows are checked, not assumed.

## Demo (non-normative)

- `node scripts/plan-ison.mjs <file.ison> [--out file] [--size WxH] [--layout fixed|force] [--demo]`: source text -> scene (`scene-core`) -> layout (`layout-core`; `fixed` is a deterministic integer grid, `force` the corpus policy `igl:F01`) -> display list -> plan, written to `demo/out/`. For `fixtures/oracles/o1-basic.source.ison` with `--layout force` the plan is the bytes of row `gl:G01` (`npm run demo:check` compares them). `--demo` also writes `demo/out/data.js`.
- `npm run demo:build` bundles the page into `demo/out/demo.js`; `demo/index.html` (serve the folder from `localhost`: hashing needs a secure context; `?software=1` accepts software GL) probes for WebGL2, draws the plan on a real `<canvas>`, and on a refusal mounts the Canvas renderer and then V5's SVG renderer by the **host's own** try-chain (fallback is never the renderer's); a click goes through `pickDrawn` and shows the typed address and the identity that `resolveSelection` finds in the embedded source.

## Limits and what is NOT claimed

- Levels 0 and 1 of IGR/1 pass by delegation to the reference renderer and prove nothing about drawing; level 2 means the plan the renderer produces accounts for each drawn element by an instance or a listed omission and for no other element (no geometry beyond the oracle bytes, no text). Every report is `claimable: false` until the kit is released and the corpus pinned.
- Shader sources are **text** pinned by a digest. The browser smoke compiled, linked and drew them on **one engine** (software GL, ANGLE/SwiftShader) on one machine; nothing else is claimed: not other drivers, not hardware GPUs, not mobile, not any other browser, not pixel parity with the Canvas renderer, not real context-loss behaviour beyond that one run, not edge accuracy beyond about 10^6 px on hardware.
- Not claimed: pixels, antialiasing, text rasterization and shaping, canvas-size limits, assistive technology, keyboard operation (V11), performance (V12).
- The `dom` adapter rebuilds the plan and the picker per commit (O(N + E) `bigint` work with no culling: design R-5, V12).
