# renderer-core (IGR/1)

`isongraph-visualize-renderer-core` is the renderer contract and conformance kit of ISONGraph Visualize milestone V4. It defines what every renderer must agree on (which objects exist, their typed identities, accessible text, selection, focus, visibility, viewport, hit-test results) and ships one executable renderer that draws nothing. It builds no SVG, Canvas or WebGL renderer. Specification: `docs/isongraph-visualize-blueprint/27-IGR1-DESIGN.md` (rev 5); ambiguity log and design findings: `docs/isongraph-visualize-blueprint/reviews/27-implementation-notes.md`.

Status: **implemented, not yet frozen.** It depends on the frozen `scene-core` (IGS/1) and `layout-core` (IGL/1) and changes neither.

## What is here

- `buildRenderModel(sceneBytes, layoutBytes, { limits? })`: one verified, branded, deep-frozen model (calls `bindLayout`); `lookupElement`, `modelBytes`, `selectionReference`, `resolveSelection`.
- `SemanticState` and its strict canonical form: `initialState`, `serializeState` (strict, never reorders), `normalizeState`, `parseState` (the ordered checks of design 4.2), `stateSha256`.
- `reduce(model, state, intent)`: the single pure reducer (select, focus, traversal, hide, pan, zoom, fit, resize); `serializeEvents`. All viewport and hit arithmetic is exact `bigint`.
- `hitTest(model, state, point)`: normative semantic hit geometry (12 px nodes, 6 px edges, closed boundaries, quantized pointer) with the stated conservative pre-filter.
- Accessibility **data model** only: names, descriptions, summary, status, announcements, `buildAccessibleModel`. No DOM, no ARIA mapping.
- `verifyManifest`, the degradation matrix, `createHeadlessRenderer()` (`./headless`): the reference `Renderer`, with the lifecycle rules of design 9.
- `RenderReport`, `semanticProjection`, `serializeProjection`, `compareProjections`.
- The conformance kit (`./conformance`, `./conformance/node`): `runConformance(subject, corpus, options)`, `loadCorpus(dir)`; report with `level`, `checked`, `unchecked`, seeds and corpus digest.

## Limits and what is NOT claimed

- Every constant (hit radii, zoom range, fit padding) and every default limit (`DEFAULT_RENDER_LIMITS`) is **provisional and unmeasured**. No latency, frame-rate or throughput claim is made; `hitTest` is O(N + E) exact `bigint` work and `reduce` validates the incoming state, so very large scenes should be run behind a worker.
- A level-1 conformance result is self-reported: it does **not** prove that anything is drawn, that elements exist in a backend, that labels or direction cues are visible, that the accessible DOM matches the `AccessibleModel`, that `host` is truthful, or that gestures map to intents. It also does **not** prove (a) that a subject is correct beyond what the corpus and tier `D` exercise: a wrapper that detects the kit's generator, or one that special-cases the public corpus scenes for every vector except `D`, is not caught (tier `D` runs on a corpus model and on a model the kit generates per seed, which mitigates but does not close this); nor (b) that optional capability declarations (`export.*`, `a11y.*`, `labels.edge`, `motion.animated`) are true: they are recorded in `unchecked`, never tested. What the kit does tie to the renderer under test: its own `manifest` must equal `subject.manifest` byte for byte, and every `probe().fidelity` must agree with it (both recorded against `L01`).
- **A report is as strong as its scope.** `rows_required` (354), `rows_run`, `partial`, `claimable` and the verdict `"incomplete"` record what ran. `level` is 0 for a partial run (`only` given, or fewer rows run than the required ids of design 13.3; a corpus lacking a required id is `INVALID_CORPUS/SCHEMA`). `REQUIRED_IDS` and `PINNED_CORPUS_DIGEST` are compiled-in constants: no option, argument or corpus can supply them, so a self-made corpus can never be reported as complete, pinned or claimable. `claimable` also needs a released kit: `KIT_DIGEST` is `"UNRELEASED"` and `PINNED_CORPUS_DIGEST` is `undefined` until freeze, so no report from this package is claimable yet.
- `scene.apply-delta` is reserved: every call fails with `UNSUPPORTED_CAPABILITY/RESERVED`. No delta semantics exist.
- The independent oracle corpus is `fixtures/oracles-igr/` (written by a separate agent from the design alone). `PINNED_CORPUS_DIGEST` is `undefined` and `KIT_DIGEST` is `"UNRELEASED"` until the corpus is frozen and the kit released; reports then say `corpus_digest_pinned: false`.
- The kit's own tests use a mini corpus generated by this package, run through an internal runner that is not exported; such a run is always partial. It shows that the kit detects deviations: every subject-level mutant of the design (K02-K82 without the core-function ones) fails its named check, with no allowance; the core-function mutants K54, K63-K67, K70, K71, K77, K79 are killed by the unit tests and by the oracle corpus at the core tier; `K37`/`K38` are tamper tests.
- No browser smoke (`smoke:browser`, a V4 closure requirement of design 7a) exists yet; `npm run smoke` runs on Node 22 and 24.

## Commands

- `npm test`: the FAST suite (about 5 s, 16 files): nothing in it builds a large model or runs a conformance pass.
- `npm run test:slow`: the SLOW suite (`test/slow`, one forked worker, files one after another): the 200,000-node models of audit C-1, whole conformance passes, and the mutation matrix against the mini corpus and (when present) fixtures/oracles-igr. Minutes, not seconds.
- `npm run check`: typecheck, `npm test`, `npm run test:slow`, build. `npm run smoke` needs the built `dist`.

### Windows: always start from an upper-case drive letter

A shell that starts in a lower-case drive (`d:...`) makes plain `npx vitest` fail every test file with `TypeError: Cannot read properties of undefined (reading config)`: Vite sees each file under two spellings, loads `vitest` twice and the test runner has no state. This is environmental (reproduced here: `cd /d/...` in Git Bash gives a lower-case `process.cwd()`; `cd D:/...` works). `npm test`, `npm run test:slow` and `npm run check` go through `scripts/vitest.mjs`, which restores the upper-case letter, so use them; a bare `npx vitest` needs an upper-case cwd.

### Memory

The slow suite needs a worker heap above 256 MB (the 200,000-node models); with `--max-old-space-size=256` that worker dies with `Worker exited unexpectedly`. The fast suite passes with 256 MB.
